Use mature foundations first

Keep language semantics, typed values, routing, ownership and errors in TypeRB. Use existing implementations for transport, TLS and database engines behind narrow owned adapters. A future replacement needs measured application benefit, conformance evidence and a sustainable maintenance cost.

TypeRB already owns managed allocation and GC, JSON values, Hex/Base64, routing and terminal editing. Existing OS/libc dependencies still apply. Focus future optimization on those TypeRB-aware boundaries before replacing security protocols or storage engines.

Read dependencies in context

Starting Web.serve loads libuv and llhttp. Other applications do not need those libraries. The HTTP provider is currently HTTP/1; this does not imply TLS, HTTP/2, streaming or a general task scheduler.

The bootstrap curl command is distinct from a future libcurl runtime dependency. HTTP/2, DNS, IDN, authentication and TLS backends can add conditional dependencies; check the selected library configuration. Do not count all optional backends as mandatory.
