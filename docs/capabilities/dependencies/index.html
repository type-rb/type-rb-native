What does Native depend on?

The current source uses platform services and a small set of external tools and libraries. Candidates below, including selected implementation directions, are not installed dependencies. Build tools, runtime libraries and system data have different distribution costs.

Read the v0.5 linking, trust and distribution policy. Adoption decisions require separate implementation and artifact qualification.

Use mature foundations first

Keep language semantics, typed values, routing, ownership and errors in TypeRB. Use existing implementations for transport, TLS and database engines behind narrow owned adapters. A future replacement needs measured application benefit, conformance evidence and a sustainable maintenance cost.

TypeRB already owns managed allocation and GC, JSON values, Hex/Base64, routing and terminal editing. Existing OS/libc dependencies still apply. Focus future optimization on those TypeRB-aware boundaries before replacing security protocols or storage engines.

Read dependencies in context

The trb/web provider currently links libuv and llhttp, including imports using only Web response values. Importing its compression middleware also links libdeflate. The compiler and programs using only trb/http values need none of these transport/compression archives. Digest, HMAC and secure comparison select static libcrypto; the full CLI also links it for REPL, while the core compiler and lockfile checksum stay independent. Compiled applications need no runtime library-directory override. The HTTP provider is currently HTTP/1; this does not imply TLS, HTTP/2, streaming or a general task scheduler.

The bootstrap curl command is distinct from a future libcurl runtime dependency. HTTP/2, DNS, IDN, authentication and TLS backends can add conditional dependencies; check the selected library configuration. Do not count all optional backends as mandatory.
