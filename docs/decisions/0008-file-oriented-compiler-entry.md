# 0008: File-Oriented Native Compiler Entry

## Status

Accepted for Gate 6A.

## Context

Gate 5 measured a real self-hosted compiler core, but its Native, recovery, and
matched Go executables received complete source contents through argv. That
kept the comparison narrow, yet it imposed operating-system argument limits,
made ordinary file errors impossible, and intentionally did not model a usable
compiler process boundary.

Gate 6 ultimately needs project loading, packages, outputs, external-tool
orchestration, incremental builds, and more than one target. Adding all of
those at once would make correctness or performance regressions difficult to
attribute. The first slice should replace only the source ingress and command
failure contract while preserving the measured compiler core and fixed point.

This repository remains experimental. The TypeRB repository must not depend on
this entry, mention this gate, or acquire a consumer-specific compatibility
surface for it.

## Decision

Self-emitted Native compiler generations accept a repository-internal
file-oriented command:

- `compiler check SOURCE` reads one file and checks it;
- `compiler emit-qbe SOURCE` reads one file and writes QBE IL to stdout;
- compiler diagnostics use stderr and status 1;
- command misuse uses stderr and status 64; and
- file-read failure uses stderr and status 66.

The implementation is TypeRB-owned. Its emitted runtime calls libc file I/O
directly and does not spawn another process. QBE and the linker remain allowed
external toolchain components, but this entry slice does not invoke them.

B0 and differential tests retain an explicit, undocumented
`--source-content MODE SOURCE` adapter. B0 does not gain the ordinary file
command because it is a recovery artifact generated by the earlier bootstrap
boundary. B1 and later generations provide both forms, with unambiguous argv
shapes. The hidden adapter has no compatibility guarantee and remains eligible
for removal when its recovery and comparison roles disappear.

The internal `compiler_main` reports a status and receives adapter-specific
diagnostic routing. This does not change TypeRB entry syntax or semantics; the
self-emitted process entry translates it into the registered experimental
command behavior.

Gate 6A must retain B1/B2/B3 QBE identity, normalized B1/B2 executable
identity, and exact agreement with the hidden path across the existing
compiler and conformance corpus. A source file beyond conservative argv limits
must succeed. Time, RSS, and stripped-size limits are registered before the
result is observed.

## Consequences

- Ordinary source input is no longer constrained by argv payload limits.
- Diagnostics and operational failures have distinct streams and statuses.
- File I/O cost can be measured separately before project and package loading
  are added.
- The compiler remains a one-file QBE producer rather than a complete product
  driver.
- The B0 recovery route stays reproducible without expanding the reference
  TypeRB compiler or bootstrap snapshot.
- libc file I/O becomes an explicit Native system dependency and must be
  included in target-portability work.
- The temporary adapter-specific diagnostic flag is internal debt to revisit
  when the compiler adopts a richer diagnostic/result boundary.

## Alternatives considered

### Keep source contents in argv

Rejected as the ordinary path because it has a hard payload ceiling and does
not represent normal compiler use. It remains only for bounded recovery and
differential testing.

### Add file operations to the bootstrap snapshot or TypeRB core

Rejected. The Native self-emitted entry can own file loading without expanding
a temporary cross-repository surface or making the reference repository aware
of this experiment.

### Implement project loading and linking in the same slice

Deferred. Those are required Gate 6 capabilities, but combining them with the
first file ingress would obscure the cost and correctness of each boundary.

### Use a shell or host-language wrapper to read the file

Rejected for the ordinary compiler entry. It would preserve a hidden host
dependency and prevent the compiler binary from demonstrating its own file and
failure behavior.
